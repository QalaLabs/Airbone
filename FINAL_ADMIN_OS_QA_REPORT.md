## 5. Public Endpoint Security Matrix (org-scoping + status filter + PII)

All 12 endpoints scope to `PUBLIC_ORG_SLUG` and filter to published/approved rows. Only PII exposure found was the placements leak — **fixed in this pass**.

| Endpoint | Org | Status filter | PII |
|---|---|---|---|
| public/pages, courses, jobs, blogs, resources, testimonials, settings | yes | PUBLISHED / APPROVED / not-closed | none |
| public/placements | yes | CONFIRMED | **was email+phone — REMOVED** |
| public/leads (POST) | yes | key+rate-limit+dedup | none in response |
| public/resource-download | yes | PUBLISHED+gated, HMAC token | none |
| v1/public/lms/certificates | implicit | ISSUED | student name (intentional, verification UX) |

### Client-controlled privileged fields — mitigated
- `user.schema` accepts `role`/`isActive` from client, but service blocks non-SUPER_ADMIN role changes, self-role changes, and deactivation of last active SUPER_ADMIN (`user.service.ts:126-152`).
- `submitAssessmentSchema` accepts `score`/`status` from client, but both consumers require `write lms_assessments` (TEACHER/ADMIN only; STUDENT is read-only with explicit comment) — `permissions.ts:121-125`.
- `changeStageSchema.toStage` client-supplied but enforced by `STAGE_TRANSITIONS` (`admission.service.ts:159-164`).

### Auth gaps
No v1 route queries the DB without a session check or being an explicitly-public path (forgot/reset password, invite accept, public verification, NextAuth — all intentional). Self-scoped `users/me`, `users/me/password`, `notifications` correctly skip `guard()`.

1. Public placements PII leak (`api/public/placements/route.ts:39-46` returned student email+phone). Root cause: over-selective `student.select`. Fix: drop email/phone. Typecheck + lint clean, live query shape verified.

**P2 — documented (no code change; minimal-change discipline)**
2. `resource-token.ts:6` falls back to `"dev-fallback-secret"` if `PUBLIC_INTAKE_KEY` unset. Inert today (key set in all env files incl. `.env.vercel.production`). Recommend fail-closed when provisioning.
3. Rate-limit keying trusts client `x-forwarded-for` first hop (`public/leads`, `resource-download`, cert verify) — evadable; recommend proxy-set IP header + shared store.

5. `users/[id]` self-PATCH bypasses `guard()` — safe via service checks; defense-in-depth gap.
6. Media asset-count badge dead (`media.repository.ts:41-51` FOLDER_SELECT lacks `assetCount`).
7. Scheduled publish fully wired but inactive until Inngest engine provisioned.
